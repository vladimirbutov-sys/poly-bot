# Спецификация: Tournament Overround Bot

## Идея

На Polymarket мультиисходные рынки (турниры с одним победителем) имеют overround — сумма Yes-цен всех участников значительно больше 100%. Это значит что No-стороны переоценены. Покупая No на ПРАВИЛЬНЫХ участников, мы получаем положительный EV.

## Математика

Турнир с N участниками. Ровно 1 победитель. Для каждого участника i:
- `Yes_i` = CLOB-цена "выиграет" (маленькая, например 3%)
- `No_i` = CLOB-цена "не выиграет" (большая, например 97%)
- `S = Sum(Yes_i)` всех участников (например 300%)

Реальная вероятность победы: `P_i ≈ Yes_i / S` (грубая оценка, overround не равномерный).

EV покупки No_i положительный когда `ratio_i < S`, где `ratio_i = Yes_i_CLOB / (1 - No_i)`.

Но из-за неравномерности overround (аутсайдеры завышены сильнее фаворитов), используем порог с запасом: `ratio < max(S * 0.5, 1.0)`.

## Стратегия бота

### Шаг 1: Поиск турниров
- Сканировать Gamma API: все neg_risk events
- Для каждого event посчитать `S = Sum(Yes_i)` из outcomePrices
- Фильтр: `S > 1.50` (overround > 50%) — ниже не хватает маржи

### Шаг 2: Отбор и приоритизация участников
Для каждого участника турнира с S > 150%:
- Получить CLOB-цены Yes и No (реальные, из стакана)
- Посчитать `ratio = CLOB_Yes / (1 - No_price_из_Gamma)`
- **Пропустить если** `ratio >= max(S * 0.5, 1.0)`
- **Отсортировать прошедших по ratio от меньшего к большему** (лучший edge первый)
- **Взять первые 20** (лимит ставок на событие)

### Шаг 3: Размещение ордеров
- Лимитные ордера GTC на No по лучшей доступной цене
- Размер: минимальный ($5 = 5 shares)
- **Не ждать fill** — выставить и забыть (GTC)
- Ставить в порядке приоритета (лучший ratio первый), до 20 на событие

### Шаг 4: Мониторинг
- Отслеживать заполнения
- После резолва турнира — подсчёт PnL
- Ожидание: 1 проигрыш (победитель) компенсируется N-1 выигрышами

## Условия запуска ставки

1. `S > 1.50` (Sum(Yes) > 150%)
2. `ratio < max(S * 0.5, 1.0)` для конкретного участника
3. Рынок открыт, не resolved
4. Ликвидность есть (ask-side не пустой)
5. No-цена >= 0.90 (минимальная, чтобы не влезать в рискованные ставки на фаворитов)

## Вопросы для проработки

1. **Как определить что event = "турнир с одним победителем"?** Не все neg_risk events — турниры. "GTA VI" — это набор независимых рынков, а "Masters 2026" — турнир.
2. **Как получать актуальные CLOB-цены для 100+ рынков?** Batch API? Или просто midpoint по одному?
3. **Когда входить?** Sum(Yes) максимален во время турнира (раунды). До начала S ≈ 100% (нет маржи). 
4. **Когда повторять?** Overround меняется — проверять каждый час? Каждый скан-цикл?
5. **Совместимость с 98_sure_bot** — использовать тот же кошелёк или отдельный?
