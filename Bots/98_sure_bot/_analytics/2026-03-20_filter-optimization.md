## 2. МАТЕМАТИЧЕСКАЯ МОДЕЛЬ P&L

### 2.1 Формула месячного P&L

```
Monthly_PnL = Bets_per_month × (WinRate × Avg_Win - LossRate × Avg_Loss)

Bets_per_month = Slots × Turns_per_day × 30 × Fill_rate

Slots = Capital / Bet_size
Turns_per_day = 24h / Avg_resolve_hours
```

### 2.2 Текущие параметры (non-neg_risk only)

```
Capital = $573
Bet_size = $10
Slots = 57
Avg_resolve = 12h
Turns/day = 2.0
Fill_rate = 34%
Avg_win = $0.088 (при avg entry 0.985)
Avg_loss = $10.00 (полная потеря)
Win_rate = 97.4% (наблюдаемый) / ~99.9% (бэктест)
```

### 2.3 Прогноз при текущих настройках (non-neg_risk, WR 99.9%)

```
Bets/month = 57 × 2.0 × 30 × 0.34 = 1,163
PnL = 1,163 × (0.999 × $0.088 - 0.001 × $10)
    = 1,163 × ($0.0879 - $0.010)
    = 1,163 × $0.0779
    = ~$90/месяц (ROI ~16%)
```

### 2.4 Критерий Келли (оптимальный размер ставки)

```
Edge = p × (win/loss ratio) - q
     = 0.999 × (0.088/10) - 0.001
     = 0.00879 - 0.001 = 0.00779

Kelly_fraction = Edge / (win/loss ratio)
               = 0.00779 / 0.0088 = 0.885

Per-bet Kelly (57 concurrent slots) = 0.885 / 57 = 1.55%
Optimal bet = $573 × 0.0155 = $8.88 ≈ $10
```

**Вывод:** $10 на ставку при $573 капитале — оптимально по Келли. При росте до $1000 → $15.

### 3.2 НАЙДЕННЫЕ ПРОБЛЕМЫ

#### ПРОБЛЕМА 1: O/U фильтр только для киберспорта (КРИТИЧЕСКАЯ)

Фильтр `check_esports_win_only` блокирует O/U, spread, handicap **только** для категории `esports`.
Единственная потеря бота — футбольный O/U рынок (soccer).

**O/U рынки ОПАСНЫ В ЛЮБОМ ВИДЕ СПОРТА:** тотал голов/очков — это пороговый рынок, где цена 97-98% ничего не гарантирует. Матч может закончиться в любую сторону.

**Решение:** Расширить фильтр на ВСЕ спортивные категории.

#### ПРОБЛЕМА 2: end_date слишком широкий для default (7 дней)

`MAX_END_DATE_DAYS = 7` — для рынков без специальной категории. Это значит рынки типа "Will X happen by March 25?" с датой закрытия через 7 дней — деньги заморожены на неделю.

**Решение:** Сократить до 3 дней (default) — это увеличит оборот.

#### ПРОБЛЕМА 3: MIN_VOLUME $3000 отсекает валидные рынки

Бэктест показал 100% win rate при vol > $3K и liq > $500 (613 рынков). Но при vol > $1K — выборка гораздо больше с тем же win rate.

**Решение:** Снизить до $1000 для увеличения потока ставок.

#### ПРОБЛЕМА 4: Слишком узкий slippage = 66% ордеров не исполняются

Текущие правила:
- 0.975-0.985: +0.3c → лимит 0.988
- 0.985-0.990: +0.2c → лимит 0.992
- 0.990-0.993: +0.1c → лимит 0.994

При таких узких spread'ах большинство ордеров не находят контрагента.

**Решение:** Расширить slippage на 0.1c в каждом диапазоне (ROI снижается на ~0.1%, но fill rate может вырасти с 34% до 50%+).

#### ПРОБЛЕМА 5: MAX_PRICE 0.993 слишком консервативный

При $10 ставке и цене 0.993: прибыль = $10/0.993 × $1 - $10 = $0.07.
При цене 0.995: прибыль = $0.05 — всё ещё положительно.

**Решение:** Поднять MAX_PRICE до 0.995 (добавляет больше кандидатов с маленьким, но гарантированным профитом).

## 7. ЧЕГО НЕ СТОИТ ДЕЛАТЬ

1. **Не снижать PRICE_THRESHOLD ниже 0.96** — нет данных бэктеста, риск растёт нелинейно
2. **Не включать neg_risk обратно** — даже при 100% win rate, заморозка на 3-5 дней убивает оборот
3. **Не увеличивать BET_SIZE больше Келли** — при $573 кап максимум $12-15
4. **Не убирать фильтр threshold markets** — крипто/финансовые "close above $X" рынки — это монетки
5. **Не делать market orders** — limit orders + slippage = контроль цены
