### Детальный разбор проблемных фильтров

#### ПРОБЛЕМА 1: O/U фильтр только для esports (КРИТИЧНАЯ — привела к потере)

Код `check_esports_win_only` в filters.py:
```python
if category != "esports":
    return True, ""  # ← ВСЕ не-esports категории ПРОХОДЯТ
```

O/U рынки опасны В ЛЮБОМ виде спорта. "O/U 4.5 goals" при 97.9% — это пороговый рынок. Один лишний гол = переворот. Рынки spread и handicap — та же логика.

**Решение:** Переименовать в `check_sports_win_only`, применять ко ВСЕМ спортивным категориям:
esports, soccer, basketball, hockey, tennis, fighting, cricket, sports_other, american_football, baseball.

#### ПРОБЛЕМА 2: end_date default = 7 дней — слишком долго

`MAX_END_DATE_DAYS = 7` для рынков без специальной категории. Avg resolve non-neg_risk = 12ч. Зачем держать капитал 7 дней?

**Решение:** `MAX_END_DATE_DAYS = 3`

#### ПРОБЛЕМА 3: MIN_VOLUME $3000 отсекает рынки

Бэктест: 100% win rate при vol > $1K, liq > $500. При vol > $3K выборка 613 рынков, при vol > $1K — значительно больше.

**Решение:** `MIN_VOLUME = 1000`

#### ПРОБЛЕМА 4: Slippage слишком узкий

Текущие правила в config.py:

| Диапазон | Slippage | Fill rate (оценка) |
|---|---|---|
| 0.96-0.975 | +0.4c | ~70% |
| 0.975-0.985 | +0.3c | ~60% |
| 0.985-0.990 | +0.2c | ~55% |
| 0.990-0.993 | +0.1c | ~45% |

Средний fill rate = 59.6%, но ROI при узком slippage выше. Расширение на +0.1c увеличит fill rate на ~10-15%, но снизит avg profit на ~$0.01/бет. Чистый эффект = больше ставок × чуть меньше прибыль = ПЛЮС.

#### ПРОБЛЕМА 5: MAX_PRICE 0.993 — отсекает безопасные рынки

При цене 0.994: profit = $10/0.994 × $1 - $10 = $0.060
При цене 0.995: profit = $0.050
Всё ещё положительно и безрисково при 100% win rate.

**Решение:** `MAX_PRICE = 0.995`, добавить slippage tier 0.993-0.995: +0.1c

## 3. МАТЕМАТИЧЕСКАЯ МОДЕЛЬ

### 3.1 Формула месячного P&L

```
Monthly_PnL = Bets_per_month × EV_per_bet

Bets_per_month = Slots × Turns_per_day × 30 × Fill_rate
EV_per_bet = WinRate × Avg_Win - LossRate × Avg_Loss

Slots = Capital / Bet_size
Turns_per_day = 24 / Avg_resolve_hours
```

### 3.2 Текущие параметры (non-neg_risk, фильтры as-is)

```
Capital        = $573
Bet_size       = $10
Slots          = 57
Avg_resolve    = 12h (медиана non-neg_risk)
Turns/day      = 2.0
Fill_rate      = 59.6%
Win_rate       = 99.9% (консервативная оценка из бэктеста)
Avg_win        = $0.088
Avg_loss       = $10.00
```

### 3.3 Прогноз: текущие настройки

```
Bets/month = 57 × 2.0 × 30 × 0.596 = 2,049
EV/bet     = 0.999 × $0.088 - 0.001 × $10 = $0.0779
PnL/month  = 2,049 × $0.0779 = ~$160
```

### 3.4 Прогноз: после оптимизации

Изменения:
- Fill rate 59.6% → 70% (шире slippage)
- Avg resolve 12h → 10h (end_date 3 дня)
- MAX_PRICE 0.995 → больше кандидатов
- O/U фильтр → win rate остаётся ≥99.9%
- MIN_VOLUME $1000 → больше кандидатов
- Avg_win $0.088 → $0.080 (чуть ниже из-за slippage и более высоких цен)

```
Slots      = 57
Turns/day  = 2.4
Fill_rate  = 70%
Bets/month = 57 × 2.4 × 30 × 0.70 = 2,874
EV/bet     = 0.999 × $0.080 - 0.001 × $10 = $0.0699
PnL/month  = 2,874 × $0.0699 = ~$201
```

### 3.6 Критерий Келли

```
p = 0.999, q = 0.001
b = avg_win / avg_loss = 0.088 / 10 = 0.0088
Edge = p × b - q = 0.999 × 0.0088 - 0.001 = 0.00779
Kelly = Edge / b = 0.00779 / 0.0088 = 0.885 (88.5%)
Per-bet Kelly (57 slots) = 0.885 / 57 = 1.55%
Optimal bet at $573 = $8.88 ≈ $10
```

$10 — оптимально. При $1000 капитала → $15.
