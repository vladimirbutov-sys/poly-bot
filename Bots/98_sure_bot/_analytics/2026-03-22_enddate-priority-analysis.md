# Гипотеза: приоритизация ставок по end_date (v2)

**Дата:** 2026-03-22
**Гипотеза:** Если ставить сначала на рынки с ближайшим end_date, капитал будет возвращаться быстрее → больше ставок → больше PnL
**Метод:** Monte Carlo (40 прогонов × 30 дней), полная конфигурация с reg + neg_risk
**Предыдущий анализ (v1) был ошибочным:** тестировал только regular без neg_risk нагрузки

---

## 1. Главный вывод

**Мой предыдущий анализ был неправильным.** Капитала НЕ хватает — **370 пропусков/мес** при варианте C (negCap=$250).

Приоритизация SHORT FIRST снижает пропуски на 43% (370 → 210), но PnL почти не меняется (+$1/мес). **Причина парадокса:** высвобожденный капитал уходит в новые neg_risk ставки, которые снова замораживаются на 50ч.

**Настоящее открытие: negCap=$100 даёт лучший PnL ($388/мес) — лучше чем negCap=$250 ($375).**

---

## 2. Почему капитала НЕ хватает (исправляю ошибку v1)

В предыдущем анализе я тестировал только regular рынки (без neg_risk). В реальности:

| Компонент | Заморожено |
|---|---|
| Regular позиции (resolve 4-25ч) | **$245** |
| Neg_risk позиции (resolve 40-65ч) | **$225** |
| **Итого заморожено** | **$470** |
| **Свободно** | **$130** |

При $130 свободных и $15/ставку — хватает на 8 ставок. А приходит ~4 рынка/час. К вечеру свободный капитал падает до **$65-70** — это 4 ставки. Пропуски неизбежны.

### Почасовая динамика капитала (Вариант C, FIFO)

| Час | Свободно | Пропусков/час |
|---|---|---|
| 6:00 | $264 | 0 |
| 10:00 | $115 | 0.5 |
| 14:00 | $81 | 1.0 |
| 18:00 | $68 | 1.0 |
| 21:00 | $64 | 1.3 |

К вечеру бот регулярно пропускает ставки из-за нехватки денег.

## 3. Результаты: приоритизация + разные neg_cap

| Конфигурация | PnL/мес | Ставок/д | SkipCap/мес | Свободно$ |
|---|---|---|---|---|
| **negCap=$100, SHORT** | **$388** | 54.2 | **14** | **$229** |
| negCap=$100, FIFO | $383 | 54.1 | 18 | $229 |
| **negCap=$250, SHORT** | **$374** | 56.6 | **210** | **$141** |
| negCap=$250, FIFO | $375 | 55.9 | 370 | $130 |
| negCap=$250, LONG (анти) | $349 | 53.0 | 362 | $119 |
| negCap=$350, FIFO | $349 | 53.1 | 723 | $102 |
| negCap=$420, FIFO | $312 | 52.2 | 911 | $97 |
| Текущая ($10/$10, neg420) | $278 | 57.0 | 678 | $89 |
| Без neg_risk, FIFO | $375 | 49.3 | 0 | $316 |

### Ключевые находки:

**1. negCap=$100 + SHORT = $388/мес (ЛУЧШИЙ результат).**
Только $90 заморожено в neg_risk → $229 свободно → почти нет пропусков (14/мес). Приоритизация даёт ещё +$5.

**2. При negCap=$250: приоритизация снижает пропуски на 43%, но PnL не растёт.**
Парадокс: бот тратит освободившийся капитал на ещё больше neg_risk ставок (13.7/д vs 13.5/д), которые замораживают капитал снова.

**3. LONG FIRST = доказательно хуже (-$26/мес при negCap=$250).**
Это подтверждает: end_date ВЛИЯЕТ на оборачиваемость. Просто при negCap=$250 эффект нивелируется neg_risk замораживанием.

**4. Высокий negCap = ухудшение PnL:**
- negCap=$100 → $388/мес
- negCap=$250 → $375/мес
- negCap=$350 → $349/мес
- negCap=$420 → $312/мес

Каждые +$100 neg_cap → примерно -$20/мес PnL. Neg_risk позиции замораживают капитал на 50ч и не дают ставить на быстрые regular рынки.

| Час | FIFO cash | SHORT cash | FIFO skip | SHORT skip |

| 6:00 | $264 | **$278** | 0 | 0 |
| 10:00 | $115 | **$128** | 0.48 | **0.24** |

SHORT держит на $10-13 больше свободного капитала и пропускает на 35-45% меньше ставок. Но эти дополнительные ставки частично уходят в neg_risk → эффект на PnL нивелируется.

## 6. Обновлённая рекомендация

Предыдущая рекомендация (Вариант C: negCap=$250, $15/$8) — **не оптимальна**.

### Новая рекомендация: negCap=$100, betReg=$15, betNeg=$8, SHORT PRIORITY

| Параметр | Было (вариант C) | Новое |
|---|---|---|
| Neg_risk cap | $250 | **$100** |
| Приоритизация | нет | **SHORT FIRST** |
| PnL/мес | $375 | **$388** |
| Пропуски/мес | 370 | **14** |
| Свободный капитал | $130 | **$229** |
| Стабильность | Средняя | **Высокая** |

**Почему $100 лучше $250:**
- Neg_risk ставка: $8, profit = ~$0.20. Resolve: 50ч. → капитал-эффективность: $0.20/50ч = $0.004/час
- Regular ставка: $15, profit = ~$0.38. Resolve: 4.4ч. → капитал-эффективность: $0.38/4.4ч = **$0.086/час**
- Regular эффективнее в **21 раз**. Каждый $1, переведённый из neg_risk в regular, приносит в 21 раз больше profit/час.

Лимит $100 на neg_risk оставляет $500 для regular, при этом не отказывается от neg_risk полностью (5.4 neg_risk ставки/день всё ещё проходят).

## 7. Как реализовать приоритизацию

В коде бота (scanner/main loop): при обработке найденных рынков — **сортировать по end_date** (ближайший первый) перед отправкой ордеров.

```python
# В месте где бот обрабатывает список qualifying markets:
qualifying_markets.sort(key=lambda m: m.get('end_date', '9999'))
```

Это простое изменение, 1 строка кода. Эффект:
- При текущем supply: +$5/мес и -75% пропусков
- При 2x supply: +$60/мес

## 8. Ограничения

1. **Resolve time по бакетам end_date** — в positions.json нет данных по бакетам (все упали в "no data"). Используются теоретические значения из первого анализа (3.8ч для 0-1d, 13.8ч для 1-2d и т.д.). Реальные значения могут отличаться.

2. **Win rate neg_risk** — все 118 resolved в scanner = 100% win. Реальный может быть 98-99%. При loss на neg_risk потеря $8 (нужно 40 wins для покрытия).

3. **Market supply** — 60 reg + 41 neg в день по scanner. Это среднее за 4 дня. Может меняться.

4. **Neg_risk resolve time** — используется 40-65ч (uniform). Реально может быть longer tail (elections, shipping).

5. **Приоритизация в коде** — предполагает что бот видит все рынки разом и может выбрать порядок. Если бот ставит по мере обнаружения (streaming), нужна логика "подождать и выбрать лучшие".
