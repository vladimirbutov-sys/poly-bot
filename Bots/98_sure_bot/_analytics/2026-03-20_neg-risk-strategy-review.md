## 2. ПРОБЛЕМА: ЗАМОРОЗКА КАПИТАЛА

### 2.1 Модель капитала

| Сценарий | Ставок/день | Avg concurrent | Нужно $$ | Monthly PnL |
|---|---|---|---|---|
| CURRENT (без neg_risk) | 33.5 | **5.3** | $53 | ~$149 |
| С neg_risk (без лимита) | 206.8 | **200.8** | $2,008 | ~$1,057 |

При текущем банкролле $700:
- **Без neg_risk:** используется 8% капитала (5.3 из 70 слотов) — огромный запас
- **С neg_risk без лимита:** нужно 201 слот, а есть только 70 → капитал кончится за 1 цикл, потом бот ждёт 2 дня пока neg_risk не разморозится

### 2.2 Риск полной заморозки

Если neg_risk без ограничений:
1. Бот ставит ~70 ставок по $10 за первые 2-3 цикла
2. Капитал кончается (все $700 в ставках)
3. Neg_risk resolves через 2 дня → бот простаивает 2 дня
4. Regular рынки (resolve за 10ч) тоже не могут работать — нет денег

Это именно то, что произошло в первые дни работы бота: баланс упал с $500 до $3.15.

## 3. РЕКОМЕНДАЦИЯ: ЛИМИТ НА NEG_RISK КАПИТАЛ

### Оптимальный вариант

**Вместо полной блокировки → лимит 50% банкролла в neg_risk позициях.**

| Настройка | Было | Предлагается |
|---|---|---|
| `check_skip_neg_risk` | Блокирует ВСЕ neg_risk | **Убрать** |
| `check_neg_risk` (лимит) | Не используется | **Активировать: MAX_NEG_RISK_FROZEN = 50% баланса** |

### Как это будет работать

1. Бот видит neg_risk рынок → проверяет: "сколько $ уже заморожено в neg_risk?"
2. Если < 50% банкролла (< $350) → ставит
3. Если ≥ 50% → пропускает, сохраняя деньги для быстрых regular рынков

### Расчёт PnL с лимитом 50%

| Метрика | Без neg_risk | С лимитом 50% | Без лимита |
|---|---|---|---|
| Слотов regular | 70 | 35 | ~5 |
| Слотов neg_risk | 0 | 35 | ~65 |
| Regular бетов/день | 33.5 | 33.5* | 33.5 |
| Neg_risk бетов/день | 0 | ~16 | ~28 |
| **Monthly PnL** | **~$149** | **~$220** | **~$160** |

*Regular не ограничены — бот ставит на все regular, а neg_risk заполняет оставшийся капитал.

С лимитом 50%: **+$71/мес (+48% PnL)** без риска полной заморозки капитала.

Без лимита — парадоксально ХУЖЕ чем с лимитом, потому что neg_risk замораживает капитал на 2 дня и блокирует быстрые regular ставки.

## 4. ДРУГИЕ ФИЛЬТРЫ — ТРЕБУЮТСЯ ЛИ ИЗМЕНЕНИЯ?

Баг с redemption НЕ влияет на остальные фильтры. Проверка:

| Фильтр | Нужны изменения? | Причина |
|---|---|---|
| check_min_price | Нет | Ценовые пороги не зависят от redemption |
| check_liquidity | Нет | Ликвидность не связана с neg_risk |
| check_end_date | Нет | End_date проверка не менялась |
| check_sports_cancelled | Нет | Спортивные проверки независимы |
| check_financial_asset | Нет | Финансовые фильтры не менялись |
| check_coin_flip | Нет | Паттерны не зависят от redemption |
| check_sports_win_only | Нет | Уже расширен на все спорты сегодня |
| check_threshold_market | Нет | Пороговые рынки не связаны с neg_risk |
| check_weather | Нет | Погодные рынки не менялись |
| check_slow_keywords | Нет | Медленные ключевые слова не связаны |
| check_stale (MIN_VOLUME) | Нет | Объём не зависит от redemption |
| check_already_bought | Нет | Дублирование не связано с neg_risk |

**Единственное изменение:** заменить `check_skip_neg_risk` на `check_neg_risk` с лимитом.

## 5. ПЛАН ДЕЙСТВИЙ

1. В `config.py`: добавить `MAX_NEG_RISK_FROZEN = 350` (50% от $700 банкролла)
2. В `filters.py`: убрать `check_skip_neg_risk` из `run_all_filters`, вернуть `check_neg_risk`
3. В `redeemer.py`: уже исправлено (getDetermined + правильный контракт)
4. Перезапустить бота

**Ожидаемый эффект:** +48% monthly PnL ($149 → $220) при сохранении запаса капитала для regular рынков.

## Методология

- Данные: 97_scanner (21,311 рынков, 10,403 решённых, 3.7 дня)
- Реальные позиции бота: positions.json (167 позиций, 56 resolved)
- Бэктест: каждый рынок проверен через все 12 фильтров бота (кроме neg_risk)
- Resolve time: scanner = время между первым и последним снимком; бот = timestamp→resolved_at
- Capital model: $700 банкролл, $10 ставка, concurrent = bets_per_day × resolve_hours / 24
