## 2. Ключевой вывод: без neg_risk деньги лежат без дела

**Без neg_risk нужно всего $260 капитала.** Всё что выше — мёртвый груз.

Это объясняет почему ROI падает с ростом банкролла: regular рынков всего 63/день, они крутятся за 10ч, нужно 26 параллельных слотов. $700 банкролл = 70 слотов, из них 44 пустуют.

**С neg_risk** каждый дополнительный $10 дают +1 слот для neg_risk, который генерирует прибыль.

## 5. Критический взгляд на эти цифры

### Что может быть лучше
- Fill rate улучшится с расширением slippage (сегодня повысили +0.1c) — больше ставок
- Больше данных сканера (сейчас 3.7 дня) могут показать больше рынков
- Новые категории рынков на Polymarket

### Что может быть хуже
- **3.7 дня данных — мало.** Может быть "удачная неделя". Нужно 2-4 недели для уверенности
- **Loss rate 0.3% — допущение.** При 0.5% PnL падает на ~15%
- **Resolve time 53ч для neg_risk** — из выборки 23 позиций. Может быть больше
- **Рынки Polymarket сезонные** — спорт, выборы, крипто циклы. Летом может быть меньше рынков
- **Конкуренция** — другие боты тоже выкупают 97%+ рынки, fill rate может падать

### Итоговая рекомендация

**С текущим банкроллом $700:**
- Включить neg_risk с cap 70% ($490 в neg_risk)
- Ожидать ~83 ставки/день, ~$119/мес, ROI 17%
- Это на **32% больше ставок** и **32% больше PnL** чем без neg_risk

**Если хочется максимум при ROI>10%:**
- Банкролл $1,500, neg_risk cap 70%
- ~111 ставок/день, ~$159/мес, ROI 10.6%

**Не стоит вкладывать больше $2,000** — ROI падает ниже 10%, и $2K в одном боте = высокий риск на малой выборке данных.

## Методология

Все цифры — из реальных данных:
- **Ставки/день:** bot_log.txt (584 строк "Placing bet", 302 "balance too low")
- **Resolve time:** positions.json (34 regular + 23 neg_risk resolved позиций с timestamps)
- **Потолок рынков:** scanner_data.json (21,311 рынков, 3.7 дней, фильтры bot'а)
- **Profit/win:** $0.078 средний (из 60 выигранных позиций, min $0.035, max $0.374)
- **Fill rate:** 31.4% из логов (138/439). Использован 60% из предыдущего расчёта (139/233 по другой методике). Разница из-за double-counting в логах
- **Loss rate:** 0.3% (консервативно, наблюдаемый 1/61 = 1.6% для бота, 7/10403 = 0.07% для сканера)
- **Capital model:** concurrent_slots = bets_per_day * resolve_hours / 24, capital_limited = min(available_slots * 24 / resolve_h, opportunities_per_day)
