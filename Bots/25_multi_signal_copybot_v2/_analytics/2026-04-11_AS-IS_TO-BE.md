# Multi-Signal Copy-Bot: AS IS vs TO BE

**Дата:** 2026-04-11
**На основе:** полный бэктест 465 позиций Denizz за 284 дня

---

## 1. ВХОД В ПОЗИЦИЮ

### 1.1 Триггер входа

**AS IS:**
- Монитор отслеживает BUY-сделки Denizz через activity API каждые 60 сек
- Покупки буферизуются по condition_id за 24ч
- Когда буфер >= MIN_PLAYER_INVESTED ($500) — срабатывает сигнал
- HP-стратегия (95-99c) работает отдельно, без буферизации

**TO BE:**
- Монитор — без изменений (activity API каждые 60 сек)
- Буферизация — без изменений (24ч по condition_id, порог $500)
- HP-стратегия **убрана** — вход через единую систему
- Добавлен параметр: **ratio** = буфер_24ч / текущий_портфель_Denizz_по_этой_позиции

---

### 1.2 Ценовой фильтр (PRICE_FILTER)

**AS IS:**
```
denizz: min 0.05, max 0.98
```
Бот не входит при цене < 5c или > 98c.

**TO BE:**
```
denizz: min 0.02, max 0.99
```
Расширен до 2-99c. HP-зона (95-99c) теперь входит в общий фильтр.

### 1.3 Размер ставки

#### AS IS: аддитивные тиеры + ценовой множитель

**Шаг 1 — Тиеры по сумме покупок Denizz за 24ч:**

| Denizz купил за 24ч | Наша ставка |
|---|---|
| < $500 | skip |
| $500+ | $30 |
| $2,000+ | +$25 = $55 |
| $5,000+ | +$50 = $105 |
| $10,000+ | +$95 = $200 |

**Шаг 2 — Ценовой множитель (по цене входа):**

| Цена | Множитель |
|---|---|
| 0-15c | ×0.7 |
| 15-50c | ×1.0 |
| 50-70c | ×0.9 |
| 70-82c | ×0.8 |
| 82-90c | ×0.4 |
| 90-98c | ×0.3 |

**Шаг 3 — BET_SCALE:** ×1.0 (live)

**Итого AS IS:**
```
наша_ставка = тиер(покупки_24ч) × множитель(цена) × BET_SCALE
```

Зависит от **одного параметра** — суммы покупок Denizz за 24ч.

#### TO BE: формула с 7 множителями

**Базовая ставка:**
```
base_bet = denizz_bet_usd × 0.002   (масштаб 1:500)
```

**Итоговая ставка:**
```
our_bet = base_bet × M_ratio × M_tier × M_slip × M_conc × M_entry × M_portsize × M_load
```

Зависит от **6 параметров** одновременно.

**Множитель 1: M_ratio** (покупка_24ч / портфель_Denizz_по_позиции)

Откалибровано на полном бэктесте 465 позиций:

| Ratio | Позиций | WR | Avg ROI | M_ratio | Обоснование |
|---|---|---|---|---|---|
| < 5% | 433 | 58.9% | +276% | **1.0** | Основная стратегия Denizz, 93% всех сделок. Базовый множитель |
| 5-15% | 21 | 81.0% | +65% | **1.3** | Лучший WR (81%), уверенная докупка |
| 15-30% | 4 | 100% | +55% | **1.5** | Все 4 выиграли, редкий сильный сигнал. Мало данных — но все положительные |
| 30-50% | 2 | 100% | +44% | **1.2** | Мало данных (2), но оба выиграли |
| 50-80% | 0 | — | — | **0.8** | Нет данных — консервативно |
| 80-100% | 1 | 100% | +4% | **0.5** | Почти новая позиция, низкий ROI |
| > 100% | 4 | 50% | -7% | **0.0** | БЛОКИРОВКА. 50% WR, отрицательный ROI, -$85K total PnL |

**Исключение:** ratio > 100% и первая покупка >= $20K → M_ratio = 0.5 (крупный первый вход — сигнал средней силы)

**Множитель 2: M_tier** (ценовой тир, по текущему best ask)

Откалибровано на полном бэктесте:

| Тир | Позиций | WR | Avg ROI | Total PnL | M_tier |
|---|---|---|---|---|---|
| 2-15c | 45 | 33.3% | +916% | +$73K | **0.4** |
| 15-50c | 138 | 47.1% | +87% | +$1,087K | **1.0** |

| 82-95c | 84 | 86.9% | +186% | +$218K | **1.2** |

Изменение от старой модели: 82-95c **повышен** до 1.2 (был 0.7). Бэктест показал WR 86.9% — лучший тир.

**Множитель 3: M_slip** (проскальзывание)

```
slippage = current_ask - denizz_entry_price
M_slip = max(0, 1 - slippage / max_allowed)
```

Допустимое проскальзывание по тирам:

| Тир | Макс slippage | При slippage = макс |
|---|---|---|
| 2-10c | 2.0c | M_slip = 0 (блокировка) |
| 10-20c | 3.0c | M_slip = 0 |
| 20-82c | 3.0c | M_slip = 0 |
| 82-88c | 2.0c | M_slip = 0 |
| 88-92c | 1.5c | M_slip = 0 |
| 92-95c | 1.0c | M_slip = 0 |
| 95-96c | 0.75c | M_slip = 0 |
| 96-97c | 0.5c | M_slip = 0 |
| 97-98c | 0.35c | M_slip = 0 |
| 98-99c | 0.2c | M_slip = 0 |

Допуск для float: slippage > max_allowed + 0.0005 → блокировка (решает баг "0.010 > 0.010")

Если slippage < 0 (мы дешевле Denizz) → M_slip = 1.0 (без штрафа, бонус через M_entry)

**Множитель 4: M_conc** (наша концентрация — сколько мы уже вложили в эту позицию)

```
concentration = наша_позиция_usd / наш_банкролл
M_conc = max(0, 1 - (concentration / 0.10)^1.5)
```

| Наша позиция | % банкролла | M_conc |
|---|---|---|
| $0 | 0% | 1.0 |
| $60 | 3% | 0.95 |
| $100 | 5% | 0.65 |
| $160 | 8% | 0.28 |
| $200+ | 10%+ | 0.0 (блокировка) |

**Множитель 5: M_entry** (наша цена vs средняя цена Denizz)

| Наша цена vs Denizz | M_entry |
|---|---|
| Мы дешевле на 3c+ | 1.2 |
| Мы дешевле на 1-3c | 1.1 |
| Одинаковая (±1c) | 1.0 |
| Мы дороже на 1-3c | 0.9 |
| Мы дороже на 3c+ | учтено в M_slip |

```
Если our_price <= denizz_avg_entry:
    M_entry = min(1.2, 1.0 + (denizz_avg_entry - our_price) / 0.05)
Иначе:
    M_entry = 1.0  (штраф уже через M_slip)
```

**Множитель 6: M_portsize** (размер портфеля Denizz по этой позиции)

Откалибровано на полном бэктесте:

| Портфель Denizz | Позиций | WR | ROI | M_portsize |
|---|---|---|---|---|
| < $500 | 0 | — | — | 0.3 |
| $500-2K | 0 | — | — | 0.5 |
| $2K-5K | 1 | 100% | +63% | 1.0 |
| $5K-20K | 0 | — | — | 0.7 |
| $20K-50K | 7 | 57% | +144% | 0.8 |
| $50K-100K | 9 | 78% | +130% | 1.2 |
| $100K+ | 448 | 60% | +266% | **1.3** |

Примечание: 96% позиций Denizz попадают в бакет $100K+ (его портфель почти всегда > $100K). Этот множитель будет почти всегда 1.3.

**Множитель 7: M_load** (загрузка нашего портфеля)

```
portfolio_load = наши_позиции_usd / наш_банкролл
M_load = max(0, (0.90 - portfolio_load) / 0.10)
```

| Загрузка | M_load |
|---|---|
| < 70% | 1.0 |
| 80% | 1.0 |
| 85% | 0.5 |
| 90%+ | 0.0 (блокировка) |

**Финальные ограничения:**
```
our_bet = clamp(our_bet, $2, min($200, $200 - existing_position, available_balance))
Если our_bet < $2 → ПРОПУСК
```

## 2. ВЫХОД ИЗ ПОЗИЦИИ

### 2.1 Следование за Denizz (follow-sell)

**AS IS:**
- Бот отслеживает продажи Denizz через activity API + snapshot diff
- On-chain верификация через CTF.balanceOf (защита от phantom sell)
- Правила выхода:
  - Denizz продал ≥ 70% позиции → продаём 100% (rule 3: big dump)
  - Denizz продал 100% → продаём 100%
  - Denizz merge (YES+NO) → продаём 100%
  - Меньшие продажи — не реагируем

**TO BE:**
- Монитор — без изменений
- On-chain верификация — без изменений
- Правила выхода **расширены**:

| Denizz sell_ratio | Наше действие | Условие |
|---|---|---|
| < 10% | **Не выходим** | Ребалансирование |
| 10-30% | Продаём **25%** | Только если мы в прибыли |
| 30-60% | Продаём **50%** | Только если мы в прибыли |
| 60-90% | Продаём **75%** | Всегда |
| > 90% | Продаём **100%** | Всегда |

**Дополнительное правило для убыточных позиций:**
- Если наш PnL < 0 И sell_ratio < 60% → **НЕ ВЫХОДИМ** (ждём стоп-лосс или восстановление)
- Если наш PnL < 0 И sell_ratio ≥ 60% → выходим (Denizz серьёзно уходит)

---

### 2.2 Стоп-лосс (без сигнала Denizz)

**AS IS:**
- Единый стоп: если цена упала на X% от входа (зависит от exit_manager)
- HP стоп: продать если цена < 80c (для позиций 95-99c)
- Time-stop: 20 дней без движения

**TO BE:**
- Стоп-лосс по ценовому тиру входа:

| Тир входа | Стоп % | Пример |
|---|---|---|
| 2-15c | -60% | Вошли по 10c → стоп на 4c |
| 15-50c | -40% | Вошли по 40c → стоп на 24c |
| 50-82c | -25% | Вошли по 65c → стоп на 49c |
| 82-95c | -15% | Вошли по 90c → стоп на 77c |
| 95-99c | -5% | Вошли по 97c → стоп на 92c |

- Time-stop: без изменений (20 дней)

---

### 2.3 Проскальзывание при выходе

**AS IS:**
- Продаём по best bid (маркет-ордер)
- HP_STOP_LOSS_SLIPPAGE = 5c допуск при стоп-лоссе

**TO BE:**
- При exit_slippage > допустимого для тира → **лимитный ордер** вместо маркетного
- Допустимое exit slippage = те же тиры что при входе

## 3. ДВУХСТУПЕНЧАТЫЙ ВХОД (новое)

### AS IS:
- Покупаем по best ask (мгновенный fill)
- Если slippage > лимита → **SKIP навсегда**

### TO BE:
```
Ступень 1: slippage ≤ лимита тира?
  ДА → BUY по best ask (мгновенно, как сейчас)

Ступень 2: slippage > лимита тира
  → Выставляем лимитку по цене (denizz_entry + max_slippage_тира)
  → Цикл каждые 5 сек, макс 30 мин:
    a) Ордер MATCHED → записываем позицию, готово
    b) Ордер CANCELLED → выходим
    c) Проверяем Denizz: вышел из позиции? → ОТМЕНЯЕМ, выходим
    d) 30 мин прошло → ОТМЕНЯЕМ, выходим
```

## 4. ON-CHAIN SYNC (новое)

### AS IS:
- Трекер ведёт JSON-файл с позициями
- Расхождения с on-chain накапливаются (ручные сделки, дубли, внешние действия)

### TO BE:
- Каждые 5 минут: `sync_with_onchain()`
- Сравнивает size_shares в трекере с реальным балансом на кошельке
- On-chain больше → корректирует трекер вверх (добавляет manual_addition)
- On-chain меньше → корректирует вниз (записывает sync sell)
- On-chain = 0 → закрывает позицию
