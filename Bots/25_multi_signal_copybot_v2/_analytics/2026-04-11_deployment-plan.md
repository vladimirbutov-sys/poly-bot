## Часть 1. Пересчет параметров для банкролла $2,700

### Формула размера ставки

**Старая формула** (калибровка под $2,000):
```
our_bet = 31.75 * ln(x) - 177       cap = $150, max_position = $200
```

**Новая формула** (калибровка под $2,700):
```
our_bet = 43.96 * ln(x) - 253.21    cap = $200, max_position = $300
```

**Якоря калибровки:**
- Якорь 1: Denizz $500 -> наша ставка $20 (без изменений)
- Якорь 2: Denizz $30,000 -> наша ставка $200 (был $150)

**Расчет коэффициентов:**
```
a = (200 - 20) / (ln(30000) - ln(500)) = 180 / 4.0944 = 43.96
b = 20 - 43.96 * ln(500) = 20 - 273.21 = -253.21
```

### Шаг 3. Kill switch (аварийная остановка)

Kill switch -- это возможность мгновенно остановить бота, не потеряв данные.

**Способ 1 (через дашборд):** кнопка Stop в дашборде -- она уже работает, бот останавливается по PID.

**Способ 2 (ручной, если дашборд недоступен):**
```bash
# Найти PID бота
ps aux | grep "25_multi_signal_copybot"

# Остановить
kill <PID>
```

**Способ 3 (через config -- мягкая остановка):**
Добавить в config.py параметр:
```python
KILL_SWITCH = False   # поставить True чтобы бот не открывал новые позиции
```
Бот продолжит мониторить открытые позиции (exit-логика работает), но не будет входить в новые.
Это безопаснее чем полная остановка -- открытые позиции продолжают управляться.

## Часть 3. Тестирование

### 3.1. Режим тестирования

В боте уже есть `BOT_MODE = "test"` с `BET_SCALE_TEST = 0.5`. Но этот режим все равно ставит реальные деньги (просто меньшие суммы). Для безопасного тестирования 12 изменений нужен **dry-run режим**.

**Рекомендация: добавить режим `BOT_MODE = "dry-run"`**

Что он делает:
- Все вычисления проходят как в `live` (формула, множители, slippage, фильтры)
- Вместо реального ордера -- запись в лог: `[DRY-RUN] BUY $53 @ 0.85 on market XYZ`
- positions.json не меняется (или ведется отдельный `positions_dryrun.json`)
- Телеграм-уведомления с пометкой `[DRY-RUN]`

Как добавить: в `entry_manager.py` в функции `execute_part1()` -- перед вызовом `place_limit_buy()` добавить проверку:
```python
if config.BOT_MODE == "dry-run":
    _log.info(f"[DRY-RUN] Would BUY {bet_usd}$ @ {order_price} on {token_id}")
    return  # не ставим ордер
```

Аналогично в `exit_manager.py` перед `place_limit_sell()`.

### 3.2. Три этапа тестирования

#### Этап 1: Проверка формул (30 минут, перед деплоем)

Ручная проверка каждого изменения на конкретных числах.

**Тест формулы ставки:**
```python
import math
def bet(x): return min(200, max(0, 43.96 * math.log(x) - 253.21))

assert abs(bet(500) - 20) < 1       # якорь 1
assert abs(bet(30000) - 200) < 1    # якорь 2
assert bet(300) < 20                 # ниже порога -> не входим
assert bet(50000) == 200             # cap работает
```

**Тест slippage с допуском:**
```python
# Старый баг: 0.010 > 0.010 = False (из-за float)
# С допуском: 0.010 > 0.010 + 0.0005 = False (правильно)
assert not (0.010 > 0.010 + 0.0005)   # точное совпадение -- пропускаем
assert (0.011 > 0.010 + 0.0005)       # реальное превышение -- блокируем
```

**Тест горизонта:**
```python
# 15 дней -> 1.0
# 45 дней -> 0.8
# 75 дней -> 0.7
# 100 дней -> 0.4
# 130 дней -> 0.0 (блокировка)
```

**Тест стоп-лосса:**
```python
# Вход по 10c -> стоп на 4c (60%)
# Вход по 40c -> стоп на 20c (50%)
# Вход по 65c -> стоп на 35.75c (45%)
# Вход по 90c -> стоп на 54c (40%)
```

**Тест follow-sell (прибыль):**
```python
# sell_ratio 15%, PnL > 0 -> продаем 25%
# sell_ratio 40%, PnL > 0 -> продаем 50%
# sell_ratio 70%, PnL > 0 -> продаем 75%
# sell_ratio 95%, PnL > 0 -> продаем 100%
```

**Тест follow-sell (убыток, кумулятивный):**
```python
# cumulative 20%, PnL < 0 -> не выходим
# cumulative 50%, PnL < 0 -> не выходим
# cumulative 60%, PnL < 0 -> продаем 75%
# cumulative 85%, PnL < 0 -> продаем 100%
```

**Тест Rule C с PnL:**
```python
# Время < 12ч, цена < 5%, PnL > 0 -> РАЗРЕШЕН (новое поведение)
# Время < 12ч, цена < 5%, PnL <= 0 -> ЗАБЛОКИРОВАН
```

#### Этап 2: Dry-run на живых данных (24-48 часов)

1. Остановить бот через дашборд
2. Внести все 12 изменений в код
3. Поставить `BOT_MODE = "dry-run"`
4. Запустить бот через дашборд

Что наблюдать:
- Бот логирует решения `[DRY-RUN] BUY/SELL` -- проверить что формулы дают ожидаемые значения
- Нет ошибок в логе (ImportError, AttributeError от удаленных HP-функций)
- Нет зависаний (двухступенчатый вход с лимиткой работает корректно)
- exit-логика не пытается продавать реальные позиции

**Проблема:** за 24-48 часов Denizz может не дать ни одного сигнала. Это нормально. Главное -- убедиться что бот стартует без ошибок и корректно обрабатывает данные.

**Важно:** пока бот в dry-run, открытые позиции НЕ управляются (exit-логика тоже в dry-run). Это опасно для 10 открытых позиций. Варианты:
- **Вариант А:** Сделать dry-run только для ENTRY (новые позиции), а EXIT оставить рабочим. Это сложнее в реализации, но безопаснее.
- **Вариант Б:** Запустить dry-run ненадолго (2-3 часа), убедиться что нет ошибок, потом перейти к этапу 3. Риск: если за 2-3 часа Denizz сделает крупную продажу -- мы не среагируем.
- **Вариант В (рекомендуемый):** Оставить старый бот работать (управляет открытыми позициями). Запустить ВТОРОЙ экземпляр бота с dry-run в отдельной папке. Он читает те же данные API, но ничего не покупает/продает.

#### Этап 3: Live с маленькими ставками (2-3 дня)

1. Остановить бот
2. Поставить `BOT_MODE = "test"` с `BET_SCALE_TEST = 0.3` (ставки ~30% от расчетных)
3. Запустить бот

Что наблюдать:
- Реальные ордера проходят? Нет ошибок API?
- Двухступенчатый вход: лимитки выставляются и отменяются корректно?
- Follow-sell: частичные продажи работают?
- Позиции корректно записываются в positions.json?
- On-chain sync: positions.json совпадает с реальностью?

**Длительность:** 2-3 дня. Этого достаточно чтобы увидеть 3-5 сигналов от Denizz (он торгует ежедневно).

**Важно про позиции при откате:**

Новые позиции (открытые в TO BE) содержат поля, которых нет в AS IS коде:
- `peak_player_size` (для кумулятивного follow-sell)
- Возможно другие новые поля

AS IS код **проигнорирует** неизвестные поля в JSON -- Python просто не прочитает их. Позиции продолжат управляться по старой логике (exit при sell_ratio >= 70%).

**Риск:** если позиция была открыта по новой формуле с большей ставкой (формула для $2,700 дает больше) -- при откате стоп-лосс будет считаться по старой логике. Это не критично, но потенциальный убыток на позицию может быть выше.

**Рекомендация:** после отката вручную проверить все открытые позиции в positions.json -- убедиться что суммы, entry_price и статусы выглядят нормально.
