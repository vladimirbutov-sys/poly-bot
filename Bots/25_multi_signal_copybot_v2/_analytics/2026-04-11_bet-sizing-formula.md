# Новая формула размера ставки: плавная логарифмическая функция

**Дата:** 2026-04-11
**Проект:** 25_multi_signal_copybot
**Контекст:** Замена 4-ступенчатой системы (AS IS) на плавную формулу (TO BE)

---

## Проблема текущей системы (AS IS)

Сейчас бот использует 4 ступени:

| Denizz вложил >= | Наша ставка (нарастающим итогом) |
|---|---|
| $500 | $30 |
| $2,000 | $55 |
| $5,000 | $105 |
| $10,000 | $200 |

**Главная проблема -- резкие скачки:**
- Denizz вложил $4,999 -- мы ставим $55
- Denizz вложил $5,001 -- мы ставим $105
- Разница у Denizz: $2. Разница у нас: $50 (почти вдвое!)

Ещё проблема -- $200 ставка при $10K слишком много. Это 10% банкролла одним входом, при том что зона $5K-$20K имеет самый слабый ROI (+0.9%) из всех бакетов.

---

## Выбор формулы: почему логарифм?

Рассмотрел 4 варианта:

| Подход | Плюсы | Минусы | Вердикт |
|---|---|---|---|
| **Логарифм**: `a * ln(x) + b` | Плавный рост, замедляется на больших суммах, один "переключатель" -- нет | Нужно подобрать 2 коэффициента | **Лучший выбор** |
| Степенная: `a * x^b` | Гибкая кривая | При малых b растёт слишком медленно, при больших -- слишком быстро | Не подходит |
| Корень: `a * sqrt(x)` | Простая | Рост слишком быстрый в начале, слишком медленный в конце | Хуже логарифма |
| Кусочно-линейная с 8+ точками | Точный контроль | По сути ступени, просто больше -- те же скачки, только мельче | Полумера |

**Почему логарифм лучше всего:**

1. **Плавность** -- нет скачков вообще. $4,999 и $5,001 дают почти одинаковую ставку (разница $0.001)
2. **Замедление роста** -- на больших суммах ставка растёт всё медленнее. Это правильно: разница между $5K и $10K для Denizz важнее, чем между $50K и $55K
3. **Два параметра** -- легко настроить и понять
4. **Естественный потолок** -- не нужно жёсткого cap, формула сама замедляется

## Формула

```
our_bet = 27 * ln(denizz_buy_24h) - 148
```

Где:
- `denizz_buy_24h` -- сумма покупок Denizz за 24 часа по позиции (в долларах)
- `ln` -- натуральный логарифм (логарифм по основанию e = 2.718...)
- Результат ограничен: **минимум $20, максимум $150**

**Что значит натуральный логарифм простыми словами:**
Это функция, которая растёт быстро на маленьких числах и всё медленнее на больших. Удвоение суммы Denizz ($5K -> $10K) добавляет нам фиксированную прибавку (~$19), а не удваивает ставку. Следующее удвоение ($10K -> $20K) добавляет те же ~$19. Это защищает от переставки на крупных сделках.

### Ограничения (cap и floor)

```
if our_bet < 20: our_bet = 20   # минимум $20 на вход
if our_bet > 150: our_bet = 150  # максимум $150 на один вход
```

Плюс общее ограничение: **не более $200 в одной позиции** (суммарно по всем входам). Это значит:
- Можно войти 1 раз на $150, потом долить $50 = $200 итого
- Можно войти 4 раза по $50 = $200 итого, 5-й вход заблокирован
- Нельзя войти на $150 + $150 = $300 (второй вход будет урезан до $50)

## Калибровка: откуда взялись числа 27 и 148?

Подбирал коэффициенты по двум якорным точкам из бэктест-данных:

**Якорь 1: Denizz $500 -> наша ставка $20** (минимальный вход)
- $500 -- это порог срабатывания (MIN_PLAYER_INVESTED)
- $20 -- разумный минимум (меньше не имеет смысла из-за комиссий и проскальзывания)

**Якорь 2: Denizz $10,000 -> наша ставка $101** (медианная зона)
- $10K -- верхняя граница "типичной" покупки (80% в диапазоне $500-$30K)
- $101 -- примерно 5% банкролла, хороший размер для стандартной сделки

Подставляем в формулу `our_bet = a * ln(x) + b`:
- 20 = a * ln(500) + b = a * 6.215 + b
- 101 = a * ln(10000) + b = a * 9.210 + b
- Вычитаем: 81 = a * 2.995 → **a = 27.0** (округлено)
- Подставляем: b = 20 - 27 * 6.215 = 20 - 167.8 = **-148** (округлено)

## Проверка краевых случаев

### Случай 1: Denizz вложил $500 (минимальный порог)

```
our_bet = 27 * ln(500) - 148 = 27 * 6.215 - 148 = 167.8 - 148 = $19.8
→ floor = $20 (минимум)
```

Логично: минимальный сигнал -- минимальная ставка. AS IS давал $30 -- переплата на слабых сигналах.

### Случай 2: Denizz вложил $1,000

```
our_bet = 27 * ln(1000) - 148 = 27 * 6.908 - 148 = 186.5 - 148 = $38.5 → $38
```

AS IS давал $30 (всё ещё первая ступень). TO BE уже вырос -- правильно, $1K это вдвое больше $500.

### Случай 3: Denizz вложил $5,000 (медиана его покупок)

```
our_bet = 27 * ln(5000) - 148 = 27 * 8.517 - 148 = 230.0 - 148 = $82
```

AS IS скакнул с $55 до $105 на этой границе. TO BE даёт $82 -- ровно посередине, без скачков.

### Случай 4: Denizz вложил $10,000

```
our_bet = 27 * ln(10000) - 148 = 27 * 9.210 - 148 = 248.7 - 148 = $101
```

AS IS давал $200 (максимум!). TO BE даёт $101 -- вдвое меньше. Это правильно: зона $5K-$20K имеет ROI всего +0.9%, нельзя ставить максимум.

### Случай 5: Denizz вложил $50,000

```
our_bet = 27 * ln(50000) - 148 = 27 * 10.820 - 148 = 292.1 - 148 = $144 → $144
```

Зона $20K-$50K имеет ROI +14.4% -- отличные сделки. TO BE даёт $144, близко к максимуму. Хорошо.

### Случай 6: Denizz вложил $100,000

```
our_bet = 27 * ln(100000) - 148 = 27 * 11.513 - 148 = 310.8 - 148 = $163 → cap $150
```

Зона $100K+ имеет ROI +23.4% -- лучший бакет. TO BE даёт потолок $150. Это правильно: даже при лучшем сигнале не ставим больше 7.5% банкролла за один вход. Можно долить на повышении уровня.

## Взаимодействие с другими множителями

Формула даёт **базовую ставку**. Дальше применяются множители:

```
итоговая_ставка = base_bet * price_mult * horizon_mult
```

### Пример 1: Типичная хорошая сделка

Denizz вложил $8,000, цена 40c, рынок через 20 дней:
- Base bet: 27 * ln(8000) - 148 = 27 * 8.987 - 148 = $95
- Price mult: 1.0 (цена 40c в зоне 15-82c, без снижения)
- Horizon mult: 1.0 (менее 30 дней)
- **Итого: $95**

### Пример 2: Дорогая ставка с дальним горизонтом

Denizz вложил $15,000, цена 88c, рынок через 75 дней:
- Base bet: 27 * ln(15000) - 148 = 27 * 9.616 - 148 = $112
- Price mult: 0.65 (цена 88c в зоне 82-99c, снижение по changes-v1)
- Horizon mult: 0.7 (60-90 дней)
- **Итого: $112 * 0.65 * 0.7 = $51**

### Пример 3: Крупная уверенная ставка

Denizz вложил $60,000, цена 35c, рынок через 15 дней:
- Base bet: 27 * ln(60000) - 148 = $150 (cap)
- Price mult: 1.0
- Horizon mult: 1.0
- **Итого: $150** (одним входом). Можно долить до $200 на повышении.

### Пример 4: Слабый сигнал с плохими множителями

Denizz вложил $2,000, цена 92c, рынок через 100 дней:
- Base bet: 27 * ln(2000) - 148 = $57
- Price mult: 0.65 (зона 82-99c)
- Horizon mult: 0.4 (90+ дней)
- **Итого: $57 * 0.65 * 0.4 = $15 → ниже минимума $20 → БЛОКИРОВКА входа**

Правильно: слабый сигнал ($2K), дорогая цена (92c), далёкий горизонт (100 дней) -- не стоит входить.

## Правила блокировки

После применения всех множителей:
- Если итоговая ставка < $20 → **вход заблокирован** (не стоит рисковать малой суммой)
- Если итоговая ставка > $150 → **урезать до $150** (cap одного входа)
- Если сумма по позиции >= $200 → **вход заблокирован** (концентрация)
- Если сумма по позиции + новая ставка > $200 → **урезать до (200 - уже вложено)**

## Итоговое резюме

### Что меняется

| Параметр | AS IS | TO BE |
|---|---|---|
| Тип функции | 4 ступени | Плавная логарифмическая |
| Формула | Таблица уровней | `27 * ln(x) - 148` |
| Минимальная ставка | $30 | $20 |
| Максимальная ставка (один вход) | $200 | $150 |
| Максимум на позицию | $200 | $200 (без изменений) |
| Скачок на $5K | $55→$105 (+91%) | $81→$83 (+2%) |
| Скачок на $10K | $105→$200 (+90%) | $100→$102 (+2%) |
| Ставка в слабой зоне $5K-$20K | $105-$200 | $82-$119 |

### Три главных преимущества

1. **Нет скачков** -- $4,999 и $5,001 дают разницу в $0.001, а не в $50
2. **Умереннее в слабой зоне** -- зона $5K-$20K (ROI +0.9%) получает на 20-40% меньше, чем AS IS
3. **Агрессивнее на средних суммах** -- зона $2K-$5K получает больше ($57-$82 vs $55), потому что формула растёт плавно

### Формула для реализации в коде

```python
import math

def calculate_base_bet(denizz_buy_24h: float) -> float:
    """Базовая ставка по формуле: 27 * ln(denizz_buy) - 148.
    
    Ограничения: min $20, max $150 за один вход.
    Общий лимит на позицию: $200 (проверяется отдельно).
    """
    if denizz_buy_24h < 500:
        return 0  # ниже порога, не входим
    
    raw = 27 * math.log(denizz_buy_24h) - 148
    
    if raw < 20:
        return 0  # слишком мало, блокируем
    
    return min(raw, 150)
```

**Внимание:** это только справочный код для понимания формулы. Реальный код НЕ модифицируется в рамках этого анализа.
