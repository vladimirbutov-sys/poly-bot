## Ключевые факты

- **Официальная позиция Polymarket (из fee doc):** «Makers are never charged fees. Only takers pay fees.» Maker rate = 0 для всех 11 категорий. Единственный нюанс — лимитка, исполнившаяся мгновенно, квалифицируется как taker.
- **Fee-структура:** на BUY комиссия берётся в shares, на SELL — в USDC. Формула `fee = C × p × feeRate × (p(1-p))^exp`. Пик при p=0.50, затухает к краям.
- **Методика проверки:**
  - Источник данных: `data-api.polymarket.com/activity`. Поля `fee`/`feeRate`/`isMaker` API **не возвращает**.
  - Рабочий workaround: сравнение `expected = size × price` vs `usdcSize` (фактически переведённые USDC). Для SELL разница = комиссия в USDC.
  - On-chain верификация через Polygon RPC: расшифровка TransferSingle (CTF 0x4D97...6045) и Transfer (USDC 0x2791...4174) подтверждает, что поле `usdcSize` точно равно фактическому движению USDC, а поле `size` — фактическому движению shares.
- **Выявленные платные сделки (обе на Weather-рынке с price≈0.88 и 0.992):**
  - SELL Seattle temp 11.29 @ 0.88 → ожидалось $9.9352, получено $9.8756 → fee = **$0.0596 (0.60%)**
  - SELL Austin temp 4.98 @ 0.992 → ожидалось $4.9402, получено $4.9382 → fee = **$0.0020 (0.04%)**
- **Все остальные 574 сделки** (267 BUY + 307 SELL): `usdcSize == size × price` до копеек. On-chain проверка 3-х сделок показала, что shares/USDC получены ровно в заявленном объёме — следов taker fee нет.
- **Почему BUY не виден по USDC:** комиссия на BUY берётся в shares. Но on-chain проверка двух BUY (Iran Uranium 110.91 shares, Hormuz 90.67 shares) показала, что фактически получено ровно столько же shares, сколько указано в API — то есть либо BUYs вообще не платят taker fee (maker fills), либо fee нулевой по правилам рынка.
- **Почему 2 Weather-сделки заплатили:** скорее всего это были crossing-лимитки (бот попал в существующий ордер на той же цене и взял ликвидность). Weather относится к категории с taker rate 0.025–0.05. Наблюдаемая ставка 0.6% как раз попадает в диапазон «Weather peak effective rate ~1.25%» при цене 0.88 (p(1-p)=0.1056, далеко от пика 0.25).

## Верификация на блокчейне

Расшифрованы 4 транзакции на Polygon (CTF + USDC логи):

1. **BUY Iran Uranium** (`0x67e6345a...`): USDC OUT = 36.5503 (ровно `usdcSize`), shares IN = 110.91 (ровно `size`). **Нет fee ни в USDC, ни в shares.**
2. **BUY Hormuz** (`0x4aff1b62...`): shares IN = 90.67 = `size`. **Нет fee.**
3. **SELL Iran Conflict** (`0x2ea4df82...`): USDC IN = 23.72335 = `usdcSize` = `size × price`. **Нет fee (maker fill).**
4. **SELL Seattle Temp** (`0xd24cab5c...`): USDC IN = 9.79972 + rebate-back 0.07587 = 9.8756 = `usdcSize`. Expected 9.9352. **Fee = $0.0596 (0.60%) реально списан.** Видно отдельный вывод 0.13548 USDC на fee-recipient и возврат 0.07587 — по механике Maker Rebates.

Вывод: `usdcSize` в API точно отражает net USDC движение. Механизм fee работает как документация описывает.

## Рекомендации

- **Менять стратегию размещения ордеров не нужно.** 99.65% ордеров исполняются как maker fills — лимитки попадают в книгу и ждут, пока кто-то их возьмёт. Потери в $3/год — ниже уровня шума.
- **Почему текущая стратегия работает:** хотя бот ставит лимитки по best_ask/best_bid, большинство целевых рынков (Iran, Politics, Geopolitics) имеют низкую частоту матчинга и наш ордер успевает попасть в книгу до того, как появится встречный taker. Fills проходят как maker.
- **Если хочется гарантии 0% fee:** ставить BUY-лимитки на `best_ask - 1 tick` (не агрессивно), SELL-лимитки на `best_bid + 1 tick`. Минус: риск пропустить сделку при движении рынка. Для копибота с коротким окном реакции это может ухудшить fill rate — не стоит того ради $3/год.
- **Следить за Weather/Crypto-рынками:** именно там taker rate выше (Crypto 7.2%). Если бот начнёт активно торговать на них — пересмотреть. Сейчас Weather — это 3 сделки из 576, некритично.
- **Geopolitics = 0% fee на taker тоже** (по официальной таблице). Большая часть портфеля (Iran/Hormuz/Trump) попадает под Politics (4% taker peak) или Geopolitics (0%) — здесь опасности почти нет.
