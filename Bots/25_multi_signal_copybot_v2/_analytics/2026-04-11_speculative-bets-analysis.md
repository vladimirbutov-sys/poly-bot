## 4. Паттерн: спекулятивные multi-outcome ставки

### Характеристики паттерна (на примере "Which countries will send warships"):

1. **Групповой рынок** — одно событие с несколькими под-рынками (разные страны: US, UK, France и т.д.)
2. **Цена основного исхода — высокая (70-90c)** — Denizz ставит на "очевидный" исход (US точно пошлёт)
3. **Массированный вход** — ~$8,700 за 10 минут (12:50–13:00)
4. **Быстрая прибыль** — купил по ~79c, продал по 93c через ~1 час = +18%
5. **Re-entry** — после продажи перезашёл по 91c (ещё $1,700)
6. **Параллельные ставки** — одновременно Hormuz Traffic ($11K+), 10 Ships ($78)

### Почему текущий бот плохо справляется:

| Ограничение | Как мешает |
|---|---|
| **$500 буферизация** | 10 Ships ($78) не прошёл порог — сигнал потерян |
| **Rule C (whipsaw)** | Заблокировал re-entry после продажи (10 скипов!) |
| **Задержка сигнала** | 3 часа между реальной покупкой Denizz и нашим сигналом |
| **Маленький размер ставки** | $22 при ставке Denizz $2,326 (0.9% от его позиции) |
| **Slippage на tier upgrade** | Третий ордер по 0.87 — Denizz в этот момент покупал по 0.72 |

## 7. Предложение: сценарий для спекулятивных multi-outcome ставок

### Как определять спекулятивную multi-outcome ставку

Триггер: Denizz за последние **30 минут** купил в **2+ под-рынках** одного event_slug, или купил на **$2,000+** за один раз в рынке с ценой 50-95c.

Дополнительные признаки:
- event_slug содержит "which-countries" или аналогичные мульти-исходы
- Цена 50-95c (не дешёвый лонгшот, но и не "уже случилось")
- Denizz входит крупно ($2K+) и быстро (несколько покупок за минуты)

### Параметры входа

| Параметр | Стандартный | Спекулятивный |
|---|---|---|
| **Порог буферизации** | $500 | **$200** (для под-рынков одного события) |
| **Скорость входа** | Ждём best ask | **Агрессивный**: покупаем по best ask + 1c |
| **Размер ставки** | По тиерам ($22-$200) | **x1.5** от стандартных тиеров |
| **Max slippage** | По таблице (2-3c) | **+1c** сверху стандартного |
| **Rule C после выхода** | 5% порог, блокирует re-entry | **Отключить Rule C** для спекулятивных |

### Нужно ли отключать $500 буферизацию?

**Да, частично.** Для под-рынков одного события нужно считать **сумму по всему event_slug**:

```
Denizz купил:
  US warships: $2,326
  UK warships: $300
  France warships: $200
  10 ships transit: $78
  
Сумма по event = $2,904 → СИГНАЛ для каждого под-рынка
```

Сейчас каждый под-рынок считается отдельно, и мелкие ($78, $200) отсекаются.

### Размер ставки

При банкролле $2,000 и EV x1.2-x1.5 на одну сделку:
- Базовый: **$40-60** на каждый под-рынок (если 3-4 под-рынка, это $120-240 суммарно)
- Агрессивный: до **$80** на основной исход (US, самый вероятный)
- Хеджирование: **не ставить на все** — выбирать 2-3 наиболее вероятных

### Стратегия выхода

| Ситуация | Действие |
|---|---|
| Denizz продал 100% | Follow-sell немедленно |
| Denizz продал 50-70% | Продать 50% нашей позиции |
| Цена выросла на +15% от входа | Продать 50% (зафиксировать прибыль) |
| Denizz re-buy после продажи | **Входить снова** (без Rule C) |
| Цена упала -30% от входа | Стоп-лосс |

### Скорость реакции

Критично: задержка 3 часа убила большую часть прибыли. Причина — бот увидел сигнал только когда буфер по этому рынку перешёл порог, или мониторинг пропустил ранние покупки.

**Предложение:** для event_slug, где Denizz уже активен на другом под-рынке — **мгновенный сигнал** без буферизации $500.

## 8. Риски и ограничения

### Критические:

| Риск | Вероятность | Последствие |
|---|---|---|
| **Ликвидность на дешёвых рынках** | Высокая | На "UK warships" по 10c стакан может быть $50 — наш ордер $40 сдвинет цену на 5-10c |
| **Denizz покупает "корзину" — часть позиций убыточна** | Средняя | Из 5 стран Denizz выиграет на 2-3, проиграет на 2-3. Мы копируем всё — ту же дисперсию |
| **Slippage на быстром движении** | Высокая | Denizz входит первый и двигает цену. Мы входим позже, дороже |
| **Наш банкролл $2,000 vs Denizz $8,700** | Постоянная | Мы не можем пропорционально копировать. $150 на рынке, где Denizz ставит $8K — мы видим те же риски, но не можем усреднять |
| **Rule C ложные срабатывания** | Подтверждена | 10 скипов re-entry — потеряли $1,700 сигнал Denizz |

### Умеренные:

| Риск | Описание |
|---|---|
| **Overexposure** | Если ставим на 4 под-рынка по $50 = $200 (10% банкролла) — при общем обвале теряем |
| **Denizz знает больше** | Он может выйти раньше новостей, мы — с задержкой |
| **Корреляция** | Все Hormuz-рынки коррелированы — это не диверсификация |

## 9. Конкретные предложения по изменениям

### Приоритет 1: Агрегация сигналов по event_slug

**Файл:** `main.py`, логика буферизации

Вместо буферизации каждого под-рынка отдельно — считать сумму инвестиций Denizz по всему `event_slug`. Если сумма >= $500 → сигнал для каждого под-рынка, где Denizz вложил >= $50.

### Приоритет 2: Ослабление Rule C для re-entry

**Файл:** `main.py`, блок Rule C

Для рынков, где мы уже зафиксировали прибыль (PnL > 0 на закрытой позиции) — снизить порог с 5% до 2%, или полностью отключить Rule C в первые 2 часа после exit.

### Приоритет 3: Ускорение сигнала

Исследовать, почему сигнал US Warships пришёл на 3 часа позже реальных покупок Denizz. Возможные причины:
- API кеширование
- Мониторинг не видел этот token_id
- Буферизация накапливала сумму

### Приоритет 4: Sell price alignment

**Файл:** `exit_manager.py`

Мы продали по 0.880, Denizz — по 0.930. Разница 5c — это наш слиппэйдж при выходе. При цене 0.93 лучше ставить sell лимитку по 0.920 (а не 0.880), дать 30 секунд на fill.
