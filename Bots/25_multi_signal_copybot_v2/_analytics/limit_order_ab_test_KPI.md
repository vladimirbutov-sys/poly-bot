# A/B Тест: Лимитные vs Рыночные ордера — KPI и методология

## Цель эксперимента

Бот торгует рыночными ордерами. Мы хотим понять: если бы вместо рыночных ордеров мы ставили лимитные на 2% лучше текущей цены — сколько бы из них заполнилось и сколько бы мы сэкономили?

## Как работает A/B тест

- Бот продолжает торговать рыночными ордерами (реальные деньги).
- После каждой сделки фоновый поток 10-15 минут следит за ценой.
- Записывает: заполнился бы лимитный ордер на 2% лучше? За сколько минут? Какая экономия?
- Данные пишутся в `limit_ab_log.csv`.

## Колонки CSV

| Колонка | Описание |
|---|---|
| timestamp | Время записи (UTC) |
| market | Название рынка |
| direction | BUY или SELL |
| our_price | Цена, по которой мы реально купили/продали |
| our_shares | Количество shares |
| our_usd | Потраченные/полученные USD |
| limit_price_2pct | Гипотетическая лимитная цена (2% лучше) |
| best_price_in_window | Лучшая цена в окне наблюдения |
| would_fill | True/False — заполнился бы лимитный ордер |
| fill_minute | На какой минуте заполнился бы (0 = не заполнился) |
| savings_per_share | Экономия на 1 share (в USD) |
| savings_total_usd | Общая экономия (в USD) |
| window_minutes | Длительность окна наблюдения (10 для BUY, 15 для SELL) |
| checks_done | Сколько проверок цены сделано |

## KPI для принятия решения

| Метрика | Формула | Успех (внедряем лимиты) | Провал (оставляем рыночные) |
|---|---|---|---|
| Fill rate входов | заполнилось / всего BUY | >50% | <30% |
| Fill rate выходов | заполнилось / всего SELL | >60% | <40% |
| Средняя экономия на share (вход) | avg(our_price - best_price) когда would_fill=True, direction=BUY | >1.5 центов | <0.5 центов |
| Средняя экономия на share (выход) | avg(best_price - our_price) когда would_fill=True, direction=SELL | >1.0 центов | <0.3 центов |
| Суммарная экономия USD | sum(savings_total_usd) по всем would_fill=True | >$30 за 15 дней | <$10 за 15 дней |
| Средний delay cost | avg(price_after_10min - our_price) для всех BUY | <1 цент | >2.5 центов |

## Контрольные точки

| Контрольная точка | Дата | Действие |
|---|---|---|
| День 5 | 2026-04-21 | Первый срез. Проверяем fill rate. Если <10% — возможно проблема в коде. |
| День 10 | 2026-04-26 | Промежуточный отчёт. Достаточно данных для предварительных выводов. |
| День 15 | 2026-05-01 | Финальное решение: внедряем лимиты или нет. |

## Как запускать отчёт

```bash
python _report_limit_ab.py --day 5   # на 5-й день
python _report_limit_ab.py --day 10  # на 10-й день
python _report_limit_ab.py --day 15  # финальный
python _report_limit_ab.py --day 0   # тестовый (проверка что всё работает)
```

## Интерпретация результатов

- **Все KPI зелёные** — однозначно внедряем лимитные ордера.
- **Fill rate хороший, но экономия маленькая** — лимиты работают, но выгода минимальна. Можно попробовать 1% вместо 2%.
- **Fill rate низкий** — цена редко доходит до лимита за 10-15 минут. Лимиты не подходят для нашей стратегии.
- **Delay cost высокий** — цена быстро уходит после сигнала. Рыночные ордера лучше — скорость важнее экономии.
